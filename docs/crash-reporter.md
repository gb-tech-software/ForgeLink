# ForgeLink Crash Reporter

## Why it exists

ForgeLink uses a **non-standard Android Gradle configuration**: the
`com.facebook.react` Gradle plugin (`apply plugin: "com.facebook.react"`) is
**not** applied in `app/build.gradle`. The plugin ships as Kotlin *source* inside
the `@react-native/gradle-plugin` npm package and requires a Kotlin toolchain to
compile via `includeBuild` — a requirement that cannot be satisfied in CI without
significant extra setup. Instead, the plugin's behaviours are inlined manually:

- `android/settings.gradle` — no `includeBuild`; native packages are included
  as Gradle subprojects directly.
- `android/build.gradle` — `subprojects { evaluationDependsOn(':app') }` block
  replaces `com.facebook.react.rootproject`.
- `android/app/src/main/java/com/facebook/react/PackageList.kt` — hand-written
  static replacement for the autogenerated class; registers
  `RNGestureHandlerPackage`, `ReanimatedPackage`, and `RNCWebViewPackage`.

This non-standard setup introduced a **runtime crash** that occurs a few
milliseconds after launch. The exact crash origin (Java exception vs. C++ signal,
which thread, which initialisation step) could not be identified via `adb logcat`
because the developer works **exclusively from Termux on-device** — adb loopback
behaves differently from a desktop ADB connection and does not produce the
expected log stream.

The crash reporter is therefore the **only available mechanism** to read native
JVM stack traces from this device environment.

## Architecture — three cooperating layers

```
Launch
  │
  ▼
MainApplication.onCreate()
  ├─ CrashReporter.install()   ← JVM Thread.setDefaultUncaughtExceptionHandler
  └─ SoLoader.init()           ← native .so loading begins HERE

          ↓ (crash on any JVM thread)
          CrashReporter.write()
          → /sdcard/Android/data/com.forgelink/files/crash_report.txt

index.js (before AppRegistry)
  └─ ErrorUtils.setGlobalHandler()  ← JS global error handler
          ↓ (unhandled JS throw / fatal Promise rejection)
          ForgeLinkNative.appendCrashLog()
          → CrashReporter.append()
          → appended to the same crash_report.txt

Next launch → src/index.tsx
  └─ useEffect → ForgeLinkNative.readCrashReport()
          ↓ (file exists)
          <CrashReportScreen report={...} />   ← shown instead of normal app
          "Dismiss & continue" → ForgeLinkNative.clearCrashReport()
```

### Layer 1 — Native JVM handler (`CrashReporter.kt`)

Installed in `MainApplication.onCreate()` **before** `SoLoader.init()`. Catches
any unhandled exception on **any JVM thread**, including:

| Exception type | Likely cause |
|---|---|
| `UnsatisfiedLinkError` | `.so` file missing from APK, wrong ABI, missing symbol |
| `IllegalStateException` | Duplicate native module registration without `canOverrideExistingModule` |
| `NullPointerException` | Uninitialised `ReactInstanceManager` during module creation |
| `NoSuchMethodError` | API mismatch between Reanimated and the RN version |
| `ClassNotFoundException` | Hand-written PackageList references a class that doesn't exist |

Does **not** catch C++ signals (SIGSEGV, SIGABRT). If the logcat shows a native
tombstone (Fatal signal 11) rather than a Java exception, a native signal handler
would be needed (NDK `sigaction`). That is a future extension.

The report is written to `getExternalFilesDir(null)` (falls back to `filesDir`).
On Android 10+ (API 29+) no `WRITE_EXTERNAL_STORAGE` permission is needed for
the app's own external files directory.

### Layer 2 — JS global handler (`index.js`)

`ErrorUtils.setGlobalHandler` is installed **before** `AppRegistry.registerComponent`
so it is active before the component tree is constructed. Catches:

- Fatal JS exceptions during the first render
- Unhandled Promise rejections that React Native promotes to fatal errors
- Any unhandled throw in a `useEffect` or event handler

Writes via `ForgeLinkNative.appendCrashLog()` which calls `CrashReporter.append()`.
Uses fire-and-forget (`.catch(() => {})`) because the bridge may be tearing down.

### Layer 3 — On-screen display (`src/index.tsx`)

`CrashReportScreen` is a standalone component rendered at the root of the React
tree (ahead of `GestureHandlerRootView` and all other providers). On every cold
launch, an `useEffect` fires immediately — before `AsyncStorage` is read, before
any gesture or animation is set up — to check for a crash report. If one exists,
the normal app is replaced by a dark screen showing the full report text and a
"Dismiss & continue" button that deletes the file and re-renders the normal app.

## File inventory

| File | Role |
|---|---|
| `android/app/src/main/java/com/forgelink/CrashReporter.kt` | Core singleton: install handler, write/append/read/clear file |
| `android/app/src/main/java/com/forgelink/ForgeLinkNativeModule.kt` | Bridge methods: `appendCrashLog`, `readCrashReport`, `clearCrashReport` |
| `android/app/src/main/java/com/forgelink/MainApplication.kt` | Calls `CrashReporter.install()` before `SoLoader.init()` |
| `index.js` | Installs `ErrorUtils` global handler before `AppRegistry` |
| `src/index.tsx` | `CrashReportScreen` component + `readCrashReport` check on mount |
| `docs/crash-reporter.md` | This document |

## Crash report file

```
/sdcard/Android/data/com.forgelink/files/crash_report.txt
```

Readable without root in any file manager (e.g. Material Files, MiXplorer).

Format:

```
=== ForgeLink Crash Report ===
Time   : 2026-07-16 14:32:01.442
Thread : mqt_native_modules (id=42, group=main)

--- Exception ---
java.lang.UnsatisfiedLinkError: dlopen failed: library "libreanimated.so" not found
    at java.lang.Runtime.loadLibrary0(Runtime.java:1087)
    at com.swmansion.reanimated.ReanimatedModule.initializeReanimated(...)
    ...

--- Device ---
Android : 14 (API 34)
Device  : Xiaomi 23013RK75C
ABI     : arm64-v8a, armeabi-v7a, armeabi
RAM     : 512MB total / 312MB free

=== JS Error ===          ← appended by JS handler (if bridge was up)
Time  : 2026-07-16T14:32:01.780Z
Fatal : true
Name  : TypeError
Msg   : undefined is not a function
...
```

## When to remove this

Remove (or simplify to a no-op) when **all** of the following are true:

1. The root-cause crash has been identified from a crash report.
2. The crash has been fixed and verified with a clean install (no report
   generated on launch).
3. An alternative diagnostics path is available (e.g. the developer has set up
   proper ADB access, or Sentry/Bugsnag has been integrated).

Until then: **do not remove or stub out any of the files or call-sites listed
above**. The reporter is the sole observability mechanism for this environment.

## Known limitations

- **C++ crashes** (SIGSEGV/SIGABRT from native code in `libreanimated.so`,
  `libhermes.so`, etc.) are **not** caught by the JVM handler. They produce
  Android tombstones in `/data/tombstones/` (root-only) and `adb bugreport`.
  If the crash is a signal rather than a Java exception, the report file will be
  empty or absent, which is itself diagnostic information.

- **Very early crashes** (before `MainApplication.onCreate()` runs) cannot be
  caught by this reporter. These are typically system-level failures and
  extremely rare.

- The report file is not rotated. A new crash overwrites the previous JVM
  section; JS sections are appended. If the app crash-loops, only the most
  recent crash is retained.
